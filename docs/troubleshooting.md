# SysGalaxy Payment Verification Gateway — Troubleshooting Manual

This manual provides diagnostic steps and solutions for common operational and integration issues encountered when deploying or integrating with **SysGalaxy Payment Verification Gateway**.

---

## 1. Quick Diagnostics Checklist

If an unexpected behavior occurs, verify the gateway status in this order:

1. **Check System Health**:
   ```bash
   curl http://localhost:3000/v1/health
   ```
   Verify that `status` is `"healthy"` and `database.status` is `"ok"`.
2. **Inspect Audit Trail**:
   Query `/v1/audit-logs` using your API key to check recent system actions, rejections, or errors.
3. **Verify API Key**:
   Ensure your request includes `Authorization: Bearer sg_test_...` (or `sg_live_...`).

---

## 2. Common Issues & Solutions

### 2.1 "Missing API key" or "Invalid API key" (401 Unauthorized)
- **Cause**: The `Authorization` header is missing, malformed, or references an API key that was revoked or from a different tenant.
- **Solution**:
  1. Confirm your header format: `Authorization: Bearer <key>`.
  2. If using `X-API-Key`, ensure the key is passed as a string.
  3. Verify that the key prefix matches your target environment (`sg_test_` vs `sg_live_`).
  4. If the key was rotated or revoked, generate a fresh key from the Admin Dashboard.

---

### 2.2 "Invalid file signature. Only authentic PNG, JPEG, WebP, and PDF receipt documents are accepted." (400 / 422)
- **Cause**: The uploaded file extension claims to be an image, but the binary file signature (magic bytes) does not match PNG (`89 50 4E 47`), JPEG (`FF D8 FF`), WebP, or PDF (`%PDF`).
- **Solution**:
  - Ensure the client uploads genuine image binaries, not renamed text or HTML files.
  - Check that the multipart field name is `file` or `receipt`.

---

### 2.3 "Duplicate receipt detected: This payment proof screenshot has already been used" (Rejected)
- **Cause**: The SHA-256 hash of the uploaded image matches an existing receipt already stored in the gateway for this merchant.
- **Solution**:
  - This is an intentional anti-fraud defense preventing duplicate receipt submission.
  - If a customer uploaded an outdated slip, ask them to upload the fresh receipt for this specific transaction.

---

### 2.4 Payment is Stuck in `pending_review` (Why is it not auto-verified?)
- **Cause**: This is **by design**.
  > **Invariant**: Never mark a payment verified only because OCR extracted the expected amount or because a customer uploaded a screenshot.
- **Solution**:
  - Direct automated verification occurs **only** when an authentic enterprise provider API callback or authenticated bank reconciliation statement is configured.
  - For standard workflows, an authorized reviewer must inspect the receipt in the Admin Dashboard (`Pending Reviews` tab) and approve it with the bank statement reference and notes.

---

### 2.5 Webhook Delivery Failures & Retries
- **Symptoms**: Deliveries show status `failed` or `retrying` in the Dashboard Delivery Logs.
- **Diagnostics**:
  1. Check destination server logs for HTTP `500` or timeout errors.
  2. Ensure your webhook endpoint acknowledges with an HTTP `200` response within 10 seconds.
  3. Use the **Send Test Ping** button in the Webhooks tab of the dashboard to test connectivity.
  4. Manually re-trigger any failed delivery using the **Retry** button.

---

### 2.6 Webhook Signature Mismatch
- **Cause**: Raw request body was altered or parsed by body-parser middleware before HMAC verification.
- **Solution**:
  - When computing the HMAC-SHA256 signature on your receiver, you **must** use the untouched, raw HTTP request body string.
  - Verify that your webhook secret matches the secret generated by SysGalaxy for that specific endpoint (`whsec_...`).

---

### 2.7 Port Conflict (Port 3000 or 5173 Already in Use)
- **Solution**:
  - Set a custom port in your `.env`:
    ```bash
    PORT=3001
    ```
  - For the React dashboard, Vite will automatically select the next available port or use:
    ```bash
    npm run dev -- --port 5174
    ```
